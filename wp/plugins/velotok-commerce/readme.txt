Заглушки оплаты через ЮKassa и выбора доставки, а также приёмка контента руководителем проекта.

== Description ==

Плагин фиксирует контракты оформления заказа до подключения реальных интеграций.

Оплата:

* провайдер `yookassa`, шлюз `velotok_yookassa`;
* контракт помечен `mocked: true`, как и оба режима — `test` и `prod`;
* платёжный шлюз доступен в оформлении заказа, но `process_payment()` не обращается к ЮKassa: заказ остаётся в статусе `pending`, в мета-данные пишется `_velotok_payment_mocked = true`;
* учётные данные магазина не хранятся в коде: зарезервированы имена переменных окружения `VELOTOK_YOOKASSA_SHOP_ID` и `VELOTOK_YOOKASSA_SECRET_KEY`.

Доставка:

* доступны способы `pochta` (Почта России), `cdek` (СДЭК) и `other` (иной логист);
* все способы помечены `mocked: true`;
* выбор способа обязателен на оформлении заказа и сохраняется в мета-данных заказа;
* стоимость доставки до подключения тарифов не рассчитывается.

Приёмка контента:

* обязательна (`required: true`);
* выполняет только живой человек с ролью «Руководитель проекта» (`velotok_project_manager`) и возможностью `velotok_accept_content`;
* автоматическая приёмка запрещена (`automation_allowed: false`);
* новый заказ получает статус приёмки `pending`; руководитель проекта может подтвердить или отклонить приёмку через действие в карточке заказа WooCommerce.

== Installation ==

1. Убедитесь, что установлен и активирован WooCommerce.
2. Скопируйте каталог `velotok-commerce` в `wp-content/plugins/`.
3. Активируйте плагин «Велоток: оформление заказа».
4. Назначьте роль «Руководитель проекта» сотруднику, который принимает контент.

== Contract test ==

```bash
wp eval-file wp-content/plugins/velotok-commerce/tests/contract-test.php
```

Тест проверяет наличие заглушек, маркеров `mocked: true`, всех способов доставки, роли и возможности приёмки контента. Без заглушки или без маркера `mocked: true` тест завершается с ошибкой и ненулевым кодом возврата.

== Open Questions ==

= ЮKassa: тестовый и боевой режимы =

Как разделяются test/prod, каков источник и формат учётных данных магазина, как секреты подставляются из env в runtime. В заглушке боевой режим выключен, реальные запросы не выполняются.

= Интеграция со службами доставки =

Какие API Почты России и СДЭК подключаются, какие данные и в каком объёме передаются, как обрабатывается вариант «иной логист» и кто его согласует.

= Стоимость доставки =

Источники тарифов, правила расчёта и отображение стоимости в заказе до подключения реальных интеграций. Сейчас стоимость не рассчитывается и в заказе не фиксируется.

= Вебхуки ЮKassa =

Формат уведомлений, проверка подписи, идемпотентность и порядок перевода заказа в оплаченный статус после подключения реальной интеграции.
