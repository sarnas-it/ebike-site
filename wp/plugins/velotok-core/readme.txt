Характеристики электровелосипедов для карточек товаров WooCommerce.

== Description ==

Мини-плагин добавляет к товарам WooCommerce поля контракта темы «Велоток»:

* `_velotok_tagline` — короткий слоган, строка;
* `_velotok_range_km` — запас хода в километрах, целое число от 0 до 500;
* `_velotok_motor_w` — мощность мотора в ваттах, целое число от 0 до 3000;
* `_velotok_weight_kg` — вес в килограммах, число с точкой от 0 до 500;
* `_velotok_wheel` — размер колёс, строка;
* `_velotok_badge` — бейдж (например, «Хит»), строка.

Поля доступны в редакторе товара в блоке «Характеристики велосипеда», а также через REST API. Значения санитизируются, запись защищена nonce и проверкой прав на редактирование товара.

Плагин не изменяет ядро WordPress, WooCommerce или другие плагины. При деактивации и удалении данные товаров сохраняются.

= Checkout, доставка и оплата (stub) =

Контракт оформления заказа реализован в `includes/checkout-contracts.php` и помечен `mocked => true`. Он ссылается на спеку `clarify-096bb945` и содержит:

* оплату через ЮKassa — заглушка шлюза `velotok_yookassa_stub` (`includes/payment-gateway.php`), реальные деньги не списываются;
* выбор способа доставки `velotok_delivery_method`: `postal_rf` («Почта РФ»), `cdek` («СДЭК») и `other_logist` («Иной логист»);
* обязательную приёмку контента и заказа человеком с ролью «Руководитель проекта» (`project_lead`) и возможностью `velotok_accept_order`.

В WooCommerce регистрируются три mocked-метода доставки с нулевой стоимостью. Реальные API Почты РФ, СДЭК и иного логиста не вызываются. Выбранный способ сохраняется в мета-поле заказа `_velotok_delivery_method`.

Нерешённые вопросы по интеграциям: разделение test/prod ЮKassa, источник и формат учётных данных магазина, подстановка секретов из env, состав API логистов, передаваемые данные, обработка варианта «иной логист» и источники тарифов доставки.

Запуск контрактного теста:

```bash
php wp/plugins/velotok-core/tests/checkout-contract-test.php
node wp/plugins/velotok-core/tests/checkout-contract.test.js
node wp/plugins/velotok-core/tests/checkout-contract-negative.test.js
```

Тест падает, если заглушка удалена, не помечена `mocked: true`, теряет один из трёх способов доставки или перестаёт требовать приёмку руководителем проекта. Негативный тест отдельно проверяет, что без файла заглушки контрактный тест действительно завершается с ошибкой.

== Installation ==

1. Убедитесь, что установлен и активирован WooCommerce.
2. Скопируйте каталог `velotok-core` в `wp-content/plugins/`.
3. Активируйте плагин «Велоток: поля товара» в разделе «Плагины».
4. Откройте любой товар и заполните блок «Характеристики велосипеда».

== Frequently Asked Questions ==

= Что будет, если WooCommerce не активен? =

Плагин не ломает сайт и показывает администратору уведомление о необходимости активировать WooCommerce.

= Удаляются ли характеристики при удалении плагина? =

Нет. Поля товаров считаются данными клиента и сохраняются.
