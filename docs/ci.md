# CI

## Причина no_checks по PR #5

В момент коммита `a6f85f6d4f8bb7b71a49d5a72316bc208d188fdf` в репозитории
не было ни одного workflow: на ветке `main` и на ветке PR #5 каталог
`.github/workflows` отсутствовал. Поэтому событие `pull_request` для этого
коммита не могло создать ни одного прогона, а трекер видел
`no checks reported for the pull request`.

Отключённые Actions, фильтры по путям, очередь раннеров и лимит минут не были
причиной: запускать было нечего. Интеграция GitHub в трекере тоже работала —
через неё созданы PR #5 и PR #8. После добавления workflow в PR #8 его прогоны
для коммита `f0f5456f04ce5776a2d289754d82f6527f5067de` завершились успешно
(`push` run 41969468543 и `pull_request` run 41969469409), то есть раннеры и
права токена в порядке.

## Что исправлено

Добавлен workflow `.github/workflows/ci.yml`:

* запускается на каждом `pull_request` без фильтров по веткам и путям;
* запускается на любой `push` и вручную через `workflow_dispatch`;
* имеет таймаут 10 минут, чтобы отсутствие результата обнаруживалось раньше
  дедлайна отложенного мержа;
* использует только права на чтение содержимого репозитория.

Проверки выполняет `scripts/ci-check.sh`: синтаксис всех PHP-файлов, валидность
`content/products.json`, синтаксис shell-скриптов и контрактные тесты плагина,
если они присутствуют в проверяемом коммите.

## Восстановление проверок для PR #5

Workflow уже добавлен в ветку PR #8, но GitHub не запускает новый workflow
задним числом для старого коммита PR #5. Чтобы не переписывать историю PR #5,
добавлен `.github/workflows/recover-pr5.yml`:

1. выкачивает ровно коммит `a6f85f6d4f8bb7b71a49d5a72316bc208d188fdf`;
2. запускает на нём тот же `scripts/ci-check.sh` с PHP 8.2 и Node.js 20;
3. публикует успешный check run и commit status для этого же SHA;
4. завершает уже одобренный отложенный мерж PR #5 через API.

Job идемпотентен: если PR #5 уже смержен или его head изменился, он ничего не
делает и завершается успешно. Если проверки на старом коммите не проходят,
check run не публикуется, а мерж не выполняется. После восстановления PR #5
этот одноразовый workflow можно удалить.

## Локальный запуск

```bash
bash scripts/ci-check.sh
```

Для полного набора проверок нужны PHP 8.2+ и Node.js. Если PHP не установлен,
скрипт пропускает зависящие от него шаги и сообщает об этом.

## Настройки интеграции GitHub в трекере

Allow-list интеграции уже содержит `sarnas-it/ebike-site`: через интеграцию
созданы PR #5 и PR #8. Дополнительных изменений в настройках не требуется.
После появления workflow новые коммиты получают проверку автоматически, а для
старого коммита PR #5 проверка восстанавливается workflow
`recover-pr5.yml`.
