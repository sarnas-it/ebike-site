# CI

## Причина no_checks по PR #5

В репозитории не было ни одного workflow в `.github/workflows`, поэтому событие
`pull_request` для коммита `a6f85f6d4f8bb7b71a49d5a72316bc208d188fdf` не могло
создать ни одного прогона. Это подтверждается нулевым количеством workflow и
check runs у репозитория и PR. Отключённые Actions, фильтры по путям, очередь
раннеров и лимит минут не были причиной: запускать было нечего.

## Что исправлено

Добавлен workflow `.github/workflows/ci.yml`:

* запускается на каждом `pull_request` без фильтров по веткам и путям;
* запускается на любой `push` и вручную через `workflow_dispatch`;
* имеет таймаут 10 минут, чтобы отсутствие результата обнаруживалось раньше
  дедлайна отложенного мержа;
* использует только права на чтение содержимого репозитория.

Проверки выполняет `scripts/ci-check.sh`: синтаксис всех PHP-файлов, валидность
`content/products.json`, синтаксис shell-скриптов и контрактные тесты плагина,
если они присутствуют в проверяемом коммите.

## Локальный запуск

```bash
bash scripts/ci-check.sh
```

Для полного набора проверок нужны PHP 8.2+ и Node.js. Если PHP не установлен,
скрипт пропускает зависящие от него шаги и сообщает об этом.

## Настройки интеграции GitHub в трекере

В allow-list интеграции должен быть репозиторий `sarnas-it/ebike-site`, а в
настройках задачи должен быть разрешён приём check runs для pull request.
После появления workflow новые коммиты в PR получают проверку автоматически;
для уже открытого PR достаточно перезапустить workflow или отправить новый
коммит, после чего отложенный мерж продолжит работу без ручного вмешательства.
